## User action: deferred while iPad unavailable

No installation or new test is requested now. Inspect saved earlier exports first when supplied. This one candidate includes the existing independent diagnostics/experiments as well as the new scaler, avoiding multiple installations.

When access returns, the smallest new test is correctness plus a short diagnostic, not a claim of improved battery life:

1. Update the existing Husk guest using the normal LiveContainer installation procedure. Preserve game saves/data and both caches; do not Reset Game Data. Fully close and reopen LiveContainer/Husk after installation.
2. Dungeons settings > Game Graphics: keep selected output 2128 × 1600, Sharp / Efficient, 60 FPS, Balanced, Driver Default, LPM OFF. Start with MetalFX OFF, engine-only OFF, identification/feedback/inventory/detailed profiling OFF. Record orientation/window mode/brightness. At a reproducible camp location check the reference image and controls; save one screenshot for later same-scene comparison.
3. Enable MetalFX Spatial · 80% Input and fully restart. Keep the selected output at 2128 × 1600: do not manually lower Rendering Resolution as well. Check the startup attempt log for M9-SPATIAL experimental driver and configured input 1696 × 1280 -> output 2128 × 1600. Preflight refusal means original dimensions were retained, not that upscaling succeeded.
4. Check HUD/text, fine edges, lighting/colour, motion, touch buttons across the screen, controller movement/attacks and audio for about one minute. Capture the same scene/camera as the baseline. Report blur, distortion, flicker, ghosting or offsets. This is spatial scaling: identical reconstructed detail is not promised.
5. If rendering is correct, Gauge > Efficiency Test. GPU sampling ON for this short diagnostic; leave detailed profiling, identification/feedback/inventory and engine-only OFF. Start, mark Gameplay, dismiss the panel and play the same route about five minutes. Trigger/repeat one menu/combat effect three times and label phases if practical. Exclude panel/manual/lifecycle interruptions; retain real gameplay hitches.
6. Pause/resume once, verify correct image/controls/audio and retained input/output, then play about another minute. Stop test > Export report and JSON > Share exported files. Send report.md + diagnostics.json, startup/attempt log if available, same-scene screenshots, route/action, brightness, charging state, visible stalls, warmth and any correctness issue.
7. Disable MetalFX and fully restart. Confirm original driver, 2128 × 1600 guest swapchain, graphics and controls return. Keep the existing caches; experimental cache is separate. Stop immediately on crash, blank/corrupt rendering, uncapped behaviour or substantial new stutter; restore MetalFX and all diagnostics OFF, Balanced/Driver Default and full restart. Share failure evidence if available.
8. Analyse this result before requesting another run. The new experimental cache may initially compile more pipelines: compare first/cold with first/cold and matched warm routes with matched warm routes. Do not treat startup cache differences as a measured scaling regression or improvement.

No long battery/temperature test is required for this first smoke. A later controlled energy comparison must use diagnostics OFF, matched brightness/scene/cache/charging/ambient/starting temperature, repeated runs and scaler startup cost where relevant. Battery percentage remains coarse; watts and degrees require external tools. M3 evidence decides whether the lower input plus scaler reduces net GPU work; it cannot be assumed from fewer pixels. Adaptive Trial requires its own separate energy comparison.
