## Requested test: one installation, two short diagnostic sessions

Purpose: validate actual M4 GPU timestamps and identify recurring expensive pipeline groups in the same run. This is not a power/energy A/B. Allow about 12–15 minutes including setup, two approximately five-minute sessions, exports and restart. No additional limiter/Adaptive/long battery comparison is requested until these files are analysed.

1. Update the existing Husk guest using your usual LiveContainer IPA workflow; preserve its data and pipeline cache. Do not delete/recreate the container or clear cache. Completely close/reopen LiveContainer and launch Husk after installing.
2. Open Dungeons settings > Game Graphics. Retain Sharp / Efficient, the existing selected 2128 × 1600 fullscreen target, Frame Limit 60, Worker Scheduling Balanced and Vulkan Submission Driver Default. Set Pipeline Identification (Diagnostic) ON, Engine-only 60 FPS Limiter (Diagnostic) OFF and Driver Phase Profiling OFF. Fully restart LiveContainer/Husk again so identification applies to shader creation from launch. No MetalFX game-upscaling switch exists yet.
3. Test unplugged, Low Power Mode OFF, same orientation/window mode and fixed brightness for both sessions. You may choose a comfortable fixed brightness; record its value and do not compare drain directly with the previous 100%-brightness run. Keep the same scene/route and allow a cool starting device where practical; record warmth and any interruptions. No external measurement equipment is required for this diagnostic pair.
4. Session A: launch Dungeons and open the fullscreen toolbar's gauge button (Efficiency Test); use three fingers to restore a hidden toolbar. Turn Sample game GPU execution (Diagnostic) ON, then Start lightweight test. Set Phase marker to Gameplay, tap Done and play the same short route. After about one minute, choose a reproducible inventory/menu or combat effect: mark First-use effect in the panel, tap Done, trigger it once; mark Repeated effect, tap Done, trigger the same action three times. Continue to approximately five minutes total. Note what action you chose and visible stutters. Panel time is automatically excluded; do not exclude real compilation stalls. Use Exclude manual interruption only for an unrelated deliberate interruption and clear it before continuing.
5. Open the gauge panel > Stop test > Export report and JSON. Wait for export to finish, then Share exported files. Keep both report.md and diagnostics.json, identifying them as Session A. Export before closing; a new test replaces only the unexported in-memory session. If easily accessible, retain the attempt log too; it contains startup cache restore/checkpoint evidence outside the monitor's capture.
6. Background Husk normally so its cache checkpoint can finish before force-closing. Allow a few seconds and, if viewing the attempt log, look for checkpoint saved/unchanged. Fully close/reopen LiveContainer/Husk, retaining the cache. Session B: revisit the same scene/action, start the same GPU-enabled test, repeat the route and first/repeated action order for about five minutes, stop/export/share the second report.md + diagnostics.json. Label them Session B after restart. This is persisted-cache restart, not a cache-cleared cold test.
7. Send both exported file pairs and a short note: chosen action/route; whether resolution/sharpness, status-bar spacing, input and audio stayed correct; visible hitch timing/action; brightness, battery start/end/system-indicator readings and subjective warmth. Attach attempt log(s) if available. No need to search thousands of lines or copy individual GPU readings manually. A report saying GPU timing unavailable is still useful; share it rather than changing multiple settings to make numbers appear.
8. Stop and report any crash, blank/corrupt image, broken input/audio, uncapped operation or serious new stuttering. Restore GPU sampling OFF, Pipeline Identification OFF, Engine-only Limiter OFF, Balanced and Driver Default; fully restart after changing identification. After completing the pair, use those diagnostic-OFF baseline settings for ordinary play. Leave OS thermal safeguards intact. Heavy profiling remains OFF.
