# M1/M6/M9 interruption resilience — RESILIENCE-v1

E-M4-009 follows the previously delivered inspection repair and confirms its actual device source. Screenshot → input freeze while frames continue → unclean process end is a correctness blocker. [Raw evidence and qualified findings](runs/E-M4-009.md). The exact termination cause is unproven. This batch repairs concrete source defects and enables a focused physical regression check before resuming M2/M5 native archive validation and M3/M9 efficiency comparisons.

## Changes and review scope

1. NativeActivity onPause/onResume/focus/audio transitions now execute serially on its existing activity UiThread, the thread that executes onCreate/start/resume. UIKit only publishes the latest desired state and wakes its looper; no guest callback, cache snapshot or audio transition runs synchronously on UIKit. Requests during STARTING survive startup; duplicate/transient states coalesce in fixed memory. Callbacks run outside mailbox lock. Begin/complete sequence records and snapshot distinguish pending from acknowledged activity state. A callback can still hang; moving it does not claim otherwise.
2. Owning-scene activity, app activity and attachment jointly determine pause. Unrelated scene events do not control this game. Same-main-turn window reparenting retains the original view/layer/render target and avoids synthetic pause/resume churn. A screenshot notification records context without tearing down the drawable. Native preparation resumes through this same current visibility policy.
3. UIKit cancellation previously released only the supplied subset and then forgot all touch IDs. Now all tracked touches are cancelled/released with last mapped positions; late move/up cannot invent new IDs. UE4 ACTION_CANCEL clears its entire gesture. Virtual controls neutralise on interruption/detachment/cancellation; physical pad polling stops and sends neutral state on application inactivity, resumes by rereading controller state. Physical scene-only controller routing remains governed by GameController; it is not claimed to be a per-scene implementation.
4. Preparation waits on a utility worker for activity pause acknowledgement for at most2seconds. Missing acknowledgement skips compilation and cancels only a reserved request; active compiler work cannot be cancelled. Receipt records acknowledgement and outcome. This is not a GPU-idle guarantee; there is no queue-idle wait or readback. App/scene changes cannot force a hidden view to resume when work finishes.
5. The running-game marker retains original start/build/session and last32 bounded interruption events across inactive/background states. Previously the inactive marker was deleted, losing context when the process vanished there. Normal explicit game closure still removes it. An uncleared marker means an unclean end, not proof of crash or memory kill.
6. Fatal records use a small C signal handler with raw FD writes and immutable bounded guest image ranges prepared outside the handler. Removes Swift allocation/interpolation/backtrace, loader/logger locks and arbitrary frame walking from signal context. Leaves SIGBUS/SIGTRAP to JIT guards and SIGPIPE unchanged. Raw PC/LR/SP and available image offset aid later OS-stack correlation. OS SIGKILL/watchdog cannot be caught; native output already persists to a regular file. This is diagnostic durability, not fault recovery.
7. Classification excludes `[prev]` replay and prioritises recorded fatal signal in crash reports. Missing OBB requires actual failed startup, a main-file warning and no successful gameplay progress; a patch probe alone no longer diagnoses missing game data. Termination without cause stays unknown.
8. M1 diagnostics retain own-scene exclusions, timestamped native lifecycle events and requested/applied sequences. Bounded, event-driven only, no per-frame logs. Existing resolution/pacing/cache/driver/compiler compatibility/thermal controls preserved. Full package provenance changes; nativeABI2/schema2/compiler compatibility contract unchanged because MSL/descriptor compilation semantics did not change.

Review scope is host lifecycle/input/classifier/report/signal/prepare interactions, actual activity delivery, persistence and driver ABI compatibility regression tests. This does not establish Metal driver correctness under every OS snapshot mode, solve the unresolved CFRunLoop warning, recover lost in-memory game progress after process termination, or prove benefit/energy improvement.
