## Offline comparison/projection tooling

Run on already exported files, locally or in Codex. Nothing is transmitted by these scripts. Both are analysis tools, never automatic gate adjudicators.

```sh
python3 scripts/roadmap_progress.py docs/performance/progress/roadmap-v1.json \
  --scenario docs/performance/progress/validate-50-v1.scenario.json --output /tmp/projection.json
python3 scripts/compare_efficiency.py baseline-diagnostics.json candidate-diagnostics.json \
  --recipe relative-worker --output /tmp/comparison.json
```

Projection refuses unknown/duplicate gates, changed model/version, omitted assumptions and overwriting the source ledger/scenario. It uses a deep copy, reports actual and unearned conditional values separately, and never writes a passed-gate ledger. The saved snapshot uses the immutable031d9d2 ledger; future actual progress can be projected again without changing historical arithmetic.

The comparison recipes are strict-worker, relative-worker, engine-only, async, spatial and presentation-clock. It accepts plain/gzip exports with bounded decompression and hashes original/decoded inputs. It checks build/device/OS/session identities, actual recorded launch controls, one selected difference, diagnostic switches, protected reference settings, brightness/charging/LPM, duration/exclusions/losses, included worker treatment and spatial mechanism. It reports rates per retained host intervals, scoped CPU/work/GPU data, unknown scene/cache/ambient/starting conditions, and provenance. It never turns matching metadata, a larger cache or lower CPU time into electrical savings. Native history/host cadence remain separate from displayed frames.

Optional `--context context.json` preserves user-supplied conditions as such:

```json
{"baseline":{"route":"same camp route","cache_state":"persisted warm","case":"same case","ambient_c":null,"starting_surface_c":null},"candidate":{"route":"same camp route","cache_state":"persisted warm","case":"same case","ambient_c":null,"starting_surface_c":null}}
```

Null external values remain unknown. The checker does not read invented thermometer/watt data from Husk or grant gates from this context. Matching samples do not establish scene equality; repeated pairs and human/external evidence review remain necessary. A metadata-ready status is only preflight; missing conditions, lifetime-only admission, diagnostic overhead, incomplete GPU coverage and dirty build-stamp limitations remain explicit.
